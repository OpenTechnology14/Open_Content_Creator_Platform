## Recommended implementation order

**Critical refresh, 2026-10-12 (P-001):** earlier HCP-007/HCP-011 closure claims were too
strong for unexecuted database/provider paths. Real Postgres proved parameterized `SET` failure
and superuser/table-owner RLS bypass. Context/cleanup, separate runtime-role migration and
startup guards are repaired and live-tested. Unavailable receipt/subscription/key/push/invite
routes fail with 501 before effects, including the old unvalidated tier upgrade. The fixture
no longer deletes default volumes. Dedicated no-skip security CI lanes are added; 53 relay/10
backend checks and three actual Postgres controls pass locally. Docker/production upgrade,
real-account/hosted acceptance remain open. ComfyUI queue status has a mutation-verified deadline.

**2026-09-08 relay update (`P-058`):** the historical HCP-005/HCP-006 notes that describe both
relay managers as uninstantiated are superseded. Both apps now manage a live relay controller,
target commands by device ID, validate a compiled allowlist, and require local approval before
calling the same OBS or ComfyUI paths described in those rows. The shared protocol now discovers
authenticated same-product devices, and the server binds claimed command sources/presence to the
authenticated device before tenant fan-out. Hosted, companion and Windows acceptance remain open.

Close HCP-003, HCP-007, and HCP-008 first because they prevent a safe public repository. Then make CI truthful (HCP-001/002), establish one buildable alpha slice (HCP-004–006), and only then integrate setup/OpenTech contracts (HCP-009/010).
