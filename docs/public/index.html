Beginner path · private practice

Make a recording you can watch back

You need OBS Studio, enough free disk space for a short recording, and something to capture: a window, a game or a camera. A microphone is optional. OBS is the program that captures your picture and sound; Stream Extend adds controls around it.

This first exercise uses OBS directly. You can learn it before installing either Extend prototype. AI tools, Docker, a cloud account and a capture card are optional for this exercise; a capture card is needed only for an external video source such as a console.

  1. Choose one thing to show

    Open OBS. A scene is a layout; a source is one thing inside it. In Sources, use the add control and choose the capture option for a window, game or camera. Names vary by operating system. Pick a harmless test window instead of your entire desktop.

    Check: the preview shows only what you intended. If it is blank, confirm the chosen source and your operating system's camera or screen-recording permission.

  2. Listen before you record

    Speak into the microphone and watch its meter in the Audio Mixer. Play a little game or application audio if you want to include it. Use headphones so the speakers do not feed back into the microphone.

    Check: the intended meters move and are not muted. If sound is doubled, capture each device once and check monitoring settings.

  3. Record a short test

    Choose a recording folder in OBS Settings → Output. Use a folder you can find again. Press Start Recording, speak a sentence, make a little movement on screen, then press Stop Recording after about 20 seconds. Start Streaming is a separate action; you do not need it here.

    Check: the recording stops and a new file appears. If the file is missing, check the selected folder, free disk space and any OBS error message.

  4. Open the actual file

    Play the saved file. Confirm that your picture appears, speech is understandable, and sound matches the visible movement. A moving meter alone does not prove the recording contains the right audio.

    Done means: you have watched and heard the saved recording. If OBS saved MKV and your next tool needs MP4, use its remux function; keep the original until you have checked the converted file.

Next: prepare a clip. For installation and device details, use the capture setup reference. Streaming to an audience adds account, destination and network checks; follow the Stream setup guide when you are ready.

When something does not work

The picture is black or the camera is missing

Confirm the selected source and device, then check OS permissions. Another application may be using the camera. Close that application and retry. For an external capture card, check the cable path and the input selected in OBS.

The recording is silent, doubled or out of sync

Check the saved file first. Select the intended microphone and application audio device; avoid capturing the same audio twice. Use headphones. Change one setting, record another short test and compare before adding effects or routing tools.

Module setup shows many missing tools

Choose the task you are trying to complete. Optional AI effects and render tools are separate from a basic OBS recording. Read the check's explanation before installing anything. The current prototypes may expose more setup detail than the planned combined app.

I need to report a problem

Include the app version, OS, exact step, expected result and observed result. Use a sample recording if needed. Review any diagnostic bundle before sharing it; remove tokens, stream keys, account details and personal paths. Follow the repository's security reporting policy for vulnerabilities.

Creator path · current capabilities

Turn a finished recording into a clip

A clip is a selected part of a longer recording. Start with one clear moment and keep a copy of your original recording.

Stream Extend can register recordings from its managed recording session in the shared library. Creator Extend's Recordings inbox can show these recordings or accept a manual import. The current Start editing action records an editing status; it does not open a complete video editor.

  1. Choose the correct recording

    Open it and confirm its contents and duration. A filename or matching duration alone cannot prove it is the recording you meant.

  2. Review your start and end

    The local Shorts tool can create a browser review page, let you preview intervals and download a selected clip plan. Its setup currently requires Python and command-line steps. Use the Shorts setup and command reference; the included demo metadata describes a synthetic 90-second recording, not your own file.

  3. Render and inspect

    The render command reads the reviewed plan and source recording, then writes vertical MP4 files into a new output directory. Play each result and check framing, sound and the first and last moments before sharing.

Still being connected: the desktop inbox does not yet send a recording directly into the Shorts review-and-render workflow. Captions must be supplied; this tool does not automatically transcribe speech. It does not upload or publish your clips.

For beginners who prefer a graphical editor today, open your recording in an editor you already use. The integrated recording → review → export path is the target for the combined app.

Engineering path · inspect the evidence

Understand a workflow before extending it

The platform runs capture and latency-sensitive processing on the workstation. Cloud features are optional. Each module owns its setup and contracts; a failure in an optional module should not stop a basic local workflow.

Follow the recording boundary

  1. Read the canonical roadmap and current audit.
  2. Inspect the shared recording library for ownership, locking and profile boundaries.
  3. Read the Shorts input/output contract, including duration checks and partial-failure behavior.
  4. Use the verification matrix to choose automated and live checks.

Prepare a contribution

  1. Check the proposal queue for the authorized scope.
  2. Follow contribution setup and the owning module's instructions.
  3. Record the source revision, command, result and anything not exercised.
  4. Update the affected user guide and demonstrate recovery as well as success.

After preparing the repository's test environment, run the required offline suite from its root:

make test
git diff --check

Offline tests do not prove device capture, GPU behavior, account connections or release readiness. Consult the acceptance checklist and record live evidence where required. The repository is currently private; these source links are for authorized local reviewers.

Make material people can follow

Begin with one task, then produce an illustrated article, captioned walkthrough, transcript and short excerpt from the same verified demonstration. A draft script is not a finished video. See the generator instructions and reference review.
